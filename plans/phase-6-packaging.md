# Phase 6 – Packaging for the application

> Status: ⬜ Not started · Roadmap: `docs/PLAN.md` §3 Phase 6 · Implement with `/impl-phase 6 [step]`

## 1. Goal
A reviewer who opens the repo must understand within 2 minutes: what problem the project solves, how it is proven (tests and
numbers), and how AI was used. You have CV bullets and 2 STAR stories ready.

## 2. Scope
**In scope:** README, docs, CV bullets, STAR, demo GIF, pre-publication review of the repo.
**Out of scope:** new features. This phase writes no production code.

## 3. Prerequisites
- Phases 1 to 5 done, with real numbers in the docs.

## 4. Changes vs PLAN.md
- Add a **pre-publication review** step: no exposed personal information, passwords, or the Axon name or branding.
  Add a **docs check test** so links in the README do not break.

## 5. Design
No production code. Only one Unit test (`DocsIntegrityTest`) that checks the docs.

## 6. Steps

### - [ ] 6.1 Docs integrity test
- **Code:** `DocsIntegrityTest` (Unit): reads `README.md` and `docs/**/*.md`, checks that every relative link points to a file
  that exists; every `docs/concurrency/NN-*.md` is listed in the README; every concurrency doc has all sections of `_TEMPLATE.md`
  and no remaining `__` blanks.
- **Test:** T-6.1 no broken links; T-6.2 README lists all docs; T-6.3 templates are fully filled in.
- **Done when:** T-6.1 to T-6.3 pass.

### - [ ] 6.2 README
- Architecture diagram (taken from `docs/ARCHITECTURE.md`), 3-step run instructions, a **Hard problems solved** table (problem,
  fix, headline number, doc link), a summary benchmark table, CI badge, an AI-assisted development section (link to `AI_WORKFLOW.md`).
- **Done when:** T-6.1 and T-6.2 are green; the README can be read in about 2 minutes.

### - [ ] 6.3 Demo GIF
- Record the UI: create a case, register evidence, place a hold, run retention (held evidence is not deleted), share link
  running out of views. Save as `docs/media/demo.gif`, under 5 MB. This step is manual.

### - [ ] 6.4 `AI_WORKFLOW.md`
- At least 5 **real** entries (recorded with `/log-ai-mistake` throughout the phases). Add a "What worked well" section and the
  review process. Do not invent entries. If there are fewer than 5, state the actual count.

### - [ ] 6.5 CV bullets and STAR
- `docs/career/cv-bullets.md`: 3 bullets with real numbers taken from the docs (e.g. "zero lost/duplicate jobs across 10k jobs,
  8 workers, 20% worker crashes").
- `docs/career/star-write-skew.md` (Phase 1) and `star-fencing-token.md` (Phase 3): Situation, Task, Action, Result,
  likely interview follow-up questions, and how to answer them.
- Whether these two files are written in Vietnamese or English is up to you (see open questions). They can be kept private (git-ignored) if you want.

### - [ ] 6.6 Pre-publication review
- Search the whole repo for: the "Axon" name or branding, emails, passwords, `application-local.properties`, keys in `data/`.
  Check that git history contains no secrets. Check the license (`MIT`) and that `pom.xml` has no leftover empty tags generated by Initializr.
- **Done when:** the review checklist is recorded in the step's notes, and the repo is ready to be made public.
